# Olist Customer Feature Store Pipeline

Цей проєкт реалізує відтворюваний SQL-пайплайн для підготовки ознак (features) клієнтів на базі PostgreSQL. Створений Feature Store призначений для подальшого використання в ML-моделях прогнозування поведінки користувачів (скоринг, LTV, churn rate).

## Джерело даних
У проєкті використовується **Olist Brazilian E-commerce Public Dataset** — багатотабличний набір даних про приблизно 100 тис. замовлень на бразильській e-commerce платформі за 2016–2018 роки. 
* Офіційне джерело: [Kaggle - Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)

## Спосіб отримання файлів
Дані завантажуються автоматично під час виконання notebook у Google Colab за допомогою бібліотеки `kagglehub`. 
* **Локальна альтернатива:** Якщо виникають проблеми з Kaggle API, завантажте архів за посиланням вище, розпакуйте CSV-файли, помістіть їх у директорію `data/olist/` та розкоментуйте відповідний блок коду в першій клітинці зошита.

## Опис CTE-stages (Feature Engineering)
Пайплайн побудований у стилі аналітичних dbt/SQL-трансформацій. Він перетворює raw-дані на типізовану схему, після чого пропускає їх через ланцюжок із 7 іменованих CTE для створення клієнтських метрик:
* **`reference_date` (Stage 0):** Фіксує стабільну дату відліку для коректного розрахунку історичних метрик.
* **`stage1_orders_total`:** Об'єднує замовлення з товарними позиціями (`JOIN`), розраховуючи загальну вартість кожного чека з урахуванням доставки.
* **`stage2_rfm`:** Розраховує класичні поведінкові метрики — Recency (днів з останньої покупки), Frequency (частота) та Monetary (загальна сума).
* **`stage3_cohort`:** Визначає когорту користувача (квартал його першого замовлення).
* **`stage4_rolling_aov`:** Застосовує віконні функції (`AVG ... OVER`) для обчислення ковзного середнього чека за останні 30 днів без втрати деталізації рядків.
* **`stage5_cancel_rate`:** Обчислює історичний відсоток скасованих замовлень для кожного клієнта.
* **`stage6_category_revenue` & `stage7_preferred_category`:** Визначають найбільш пріоритетну категорію товарів клієнта (за найбільшою сумою витрат) за допомогою ранжирування `ROW_NUMBER()`.

*Примітка: Усі зведені ознаки кешуються у Materialized View (`mv_olist_customer_features`) з підтримкою `REFRESH CONCURRENTLY` для швидкого доступу (latency) під час ML-інференсу.*
